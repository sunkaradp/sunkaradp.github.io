03 / CASE NOTES

Operational details matter.

A few concrete problems from the AIcoo environment. The focus is on diagnosis, evidence and the corrective work — not inflated impact claims.

01

Database recovery is more than restoring a file.

A 158 MB database restore exposed 61 schema-drift errors. The recovery path required rebuilding the database and replaying migrations rather than treating a successful file restore as proof that the service was healthy.

Recovery process
Schema consistency
Database migrations
02

Startup failures need more than a restart.

Crash loops were traced to CPU throttling during startup. Startup behavior, CPU limits and probe timing were reviewed together, then resource and startup settings were adjusted.

Kubernetes
Resource sizing
Startup probes
03

Pipeline automation must protect runtime state.

Two workflow defects could remove runtime secrets and run migrations without required configuration. The workflows were corrected to protect runtime configuration and make migration execution explicit.

GitHub Actions
Secrets handling
Migration jobs
04

Secrets need a complete lifecycle.

After a secret exposure, the response included purging affected Git history, rotating keys and moving secret material into Sealed Secrets. Removing a value from the latest file alone was not treated as remediation.

Incident response
Credential rotation
Sealed Secrets
